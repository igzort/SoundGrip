# SoundGrip

Ритм-экшен в стиле **osu! / Fruit Ninja** для Android и ПК: на каждый удар
бочки из реально играющей музыки (захват системного звука, не микрофон)
в случайной точке экрана спавнится неоновая 3D-фигура с сжимающимся
approach-кругом. Уничтожай её свайпом точно в такт: 300 / 100 / 50.
Кольцо сжалось без свайпа — Miss.

## Архитектура

- `main.py` — Kivy-приложение, игровой цикл 60 FPS, привязка эффектов к полосам.
- `audio_capture.py` — захват аудио. На Android — MediaProjection + AudioRecord
  (jnius). На ПК — **глобальный WASAPI loopback** (весь системный микшер:
  Spotify, Chrome, YouTube, игры — всё слышно) или микрофон или демо-режим.
  Изоляция по окну/PID удалена — Windows прячет аудио плееров в audiodg.exe.
- `beat_detector.py` — детектор ударов на **спектральном потоке** (Spectral
  Flux, half-wave rectified разность соседних FFT-кадров): бочка/бас
  (30–160 Гц), снейр (200–2000 Гц), хэт (4–12 кГц). Устойчивый жирный бас
  поток не даёт → адаптивный пол не задирается на плотных дропах; после
  каждого удара **лок-аут** (кик 200 мс): порог только угасает, снейр
  следом не маскирует следующую бочку.
- `effects.py` — GPU-эффекты на кастомных шейдерах.

## Запуск с ПК (для отладки)

```bash
pip install -r requirements.txt
python main.py
```

Бекенд аудио выбирается автоматически в таком порядке:

1. `wasapi_loopback` — **глобальный системный звук** (рендер-микшер Windows
   по умолчанию): включи музыку где угодно — на биты пойдут эффекты;
2. `soundcard` — резервный глобальный loopback;
3. `soundcard` — микрофон;
3. `sounddevice` — микрофон;
4. `pyaudio` — микрофон;
5. демо-режим — синтетический драм-паттерн (кик+снейр+хэт, 120 BPM).

В статус-строке показываются бекенд, счётчики по полосам (kick/snare/hat)
и уровень прогрессии; в консоль пишутся события вида `[SoundGrip] kick+snare lvl=42%`.

## GPU-эффекты (`effects.py`)

Рисуются через кастомные шейдеры (GLSL ES 100 — один и тот же код для ПК
и Android GLES2). Формы во фрагментном шейдере:

| shape | Эффект | На что привязан |
|---|---|---|
| 0 | **Искра** (вытянута по скорости, мерцает) | снейр, хэт, взрывы |
| 1 | **Кольцо** (расширяется и гаснет) | бочка, снейр, взрывы |
| 2 | **Капля** (круглое свечение) | осколки взрывов |
| 3 | **Вспышка** (яркое ядро) | снейр, взрыв сферы |
| 8 | **Луч** (мягкий, вытянутый) | след лезвия, хэт, лазеры пирамиды |
| 11 | **Сфера-звезда** (glow 1/r² + вспышка + лучи) | **бочка/бас** |
| 12 | **Пиксель-осколок** (квадрат) | взрыв куба (pixelated shatter) |
| 13 | **Чёрная дыра** (тёмный диск + неоновый вихрь) | взрыв параллелограмма (сингулярность) |
| 18 | **Водяной пузырь** (неправильная жидкая форма, контур перетекает) | третья фигура-нота: разрез → случайный всплеск |
| 20–23 | **SDF-фигуры** (ray marching: куб/сфера/пирамида/параллелограмм) | osu!-таргеты + approach-круг |

Технические детали:
- каждая частица — квад из 2 треугольников (один Mesh-батч на всё),
  форма считается процедурно во фрагментном шейдере по UV квада;
- SDF-таргеты рисуются **ray marching'ом** (30 шагов, поворот rotY,
  нормали через конечные разности, Lambert + Specular + glow) — неоновые
  3D-фигуры на плоском квадрате;
- аддитивный блендинг через `Callback`-инструкции `glBlendFunc`
  (важно: колбэк получает инструкцию аргументом — сигнатура `(self, instr)`);
- жёсткое отсечение фона в шейдере: за пределами радиуса свечения пиксель
  прозрачен (`discard`) — никаких серых квадратных подложек;
- физика (скорость/гравитация/затухание/жизнь) — на CPU в numpy,
  буфер вершин заливается ping-pong'ом каждый кадр;
- лимиты: 1500 частиц + 24 кольца + 16 osu!-таргетов,
  мёртвые квады залиты нулями и отбрасываются в шейдере (`discard`).

### Привязка к полосам (`main.py`)

| Звук | Эффекты |
|---|---|
| **Бочка / бас / кик** (30–160 Гц) | космическая сфера-звезда с белой вспышкой ядра, тонкое кольцо |
| **Снейр** (200–2000 Гц) | вспышка-ядро + кольцо + искры |
| **Хэт / тарелки** (4–12 кГц) | радиальные лучи + искры |

### Геймплей osu! (`main.py`)

- **Спавн в такт**: умный метроном (калибровка по 5 ударам бочки →
  фазовая подстройка сетки → ямы/дропы) на каждый тик создаёт **одну
  случайную фигуру** (куб / сфера / пирамида / параллелограмм) в
  **случайной точке** экрана. Время жизни = интервал сетки (хит точно
  на следующую бочку).
- **Approach-круг**: вокруг фигуры сжимается неоновое кольцо
  (`prog: 0 → 1`), показывая момент такта; фигура плавно «вырастает»
  при появлении.
- **Свайп** (зажатая ЛКМ / палец): по пути остаётся след лезвия,
  все фигуры под отрезком свайпа уничтожаются (коллизия
  «отрезок — круг», захват 30 px вокруг курсора).
- **Очки по фазе кольца**: попадание при `prog ≥ 0.92` → **300**
  (циан), `≥ 0.72` → **100** (зелёный), иначе → **50** (жёлтый).
  Цифра всплывает над местом попадания и тает.
- **Miss**: кольцо сжалось, а свайпа не было — фигура гаснет без взрыва
  (вялый серый «пшик»), надпись **Miss**, комбо сбрасывается.
- **Очки**: считаются только **сверху, слева** (влево от полосы-стадиума) — `+10` за каждую разрезанную фигуру (`SCORE_PER_CUT`). Больше **никаких цифр и надписей в рабочей области**: ни «X серии» (`x2`, `x3` …), ни блока `xN GREAT!` — весь текст серии удалён, он висел поверх счёта. Серия попаданий подряд по-прежнему считается (для PERFECT/INCREDIBLE и итоговой панели), но на экране не отображается.
- **Обрыв серии**: на экране **ничего не появляется** — только счётчик серии обнуляется (`GameWidget._break_streak`).
- **Концовка**: по окончании трека — затемнение поля и **общий счёт** крупным кеглем 96, под ним «ОЧКОВ», лучшая серия, число разрезанных фигур и miss. Плюс **фанфары**: 6 залпов волн и искр, расходящихся от центра к краям.
- HUD: сумма очков и `combo xN / miss M`.
- **Бар PERFECT / INCREDIBLE**: полоска-«стадиум» из 5 ячеек сверху (60 %
  ширины экрана, ровно по центру). Каждые `PERFECT_AT` попаданий подряд
  дают один **PERFECT** — ровно одна целая ячейка. Полный бар включает
  режим **INCREDIBLE** на 10 с: бар жёлтым утекает до нуля, конец следа
  лезвия «сгорает» бенгальским огнём (искры в 7 раз короче прежних, живут
  0.5 с, разлёт ~3 диаметра сферы) и **искры режут**: коснулась искра
  сферы — сфера разрезана тем же путём, что свайп (см. `_spark_cuts`).
  Хитбокс лезвия при этом **базовый** (`INCREDIBLE_K = 1.0`) — усиление
  даёт сварка, а не увеличенный радиус среза.
- **Разгон по прогрессу**: сначала шары только СНИЗУ (и реже), к середине
  подключаются БОКОВЫЕ дуги, к финалу — падение СВЕРХУ ВНИЗ. Верхний режим
  в лейт-гейме летит **вдвое медленнее** (`TOP_SPEED_K = 0.5`: гравитация
  ÷4, подлёт до бита вдвое дольше), но апекс всё так же РОВНО в бит —
  такт и ритм не страдают.

### Уникальные взрывы по фигурам (`effects.py`)

| Фигура | Взрыв |
|---|---|
| **Куб** | разлетается квадратными пиксель-осколками (pixelated shatter) |
| **Сфера** | круговая ударная волна: двойное кольцо + вспышка |
| **Пирамида** | распадается на три лазерных луча под 120° |
| **Параллелограмм** | схлопывается в сингулярность (чёрная дыра с неоновым вихрем) + искры |

### Три фигуры-ноты (`main.py`)

Чередование задаёт `pick_figure(idx)`: каждая 5-я (`CUBE_EVERY`) — **кубик-Рубик**,
каждая 3-я (`WATER_EVERY`, не на месте куба) — **водяной пузырь**, остальные —
Genesis-звезда. В превью «Эффекты» любую из трёх можно форсировать.

- **Водяной пузырь** (`SHAPE_WATER = 18`): неправильная жидкая форма —
  контур «плещет» в шейдере (три синуса по углу, своя фаза у каждого
  пузыря, амплитуда до ±24 % — выраженные колебания), внутри градиент,
  мениск-кромка, блик и два плывущих пузырька.
- **Разрез** (`emit_water`): каждый раз **случайный** всплеск — 3–6 струй
  в случайных направлениях + мелкая муть (летит далеко и тает уже в
  воздухе) + 4–7 крупных капель + **пул**: 2–3 широких куска общей массы
  воды.
- **Пол**: крупные капли падают (`DEBRIS_G`), коротко скользят
  (`REST_SLIDE_T` — «растекаются»), лежат `WATER_HOLD = 0.6 с`
  и тают за `REST_LIFE`. **Пул** падает быстрее (`DEBRIS_G × 1.4`),
  растекается и лежит `WATER_POOL_HOLD = 2 с`, затем исчезает.

## Прогрессия эффектов

Эффекты нарастают вместе с мелодией: в начале — немного, максимум —
через **30 с** непрерывной музыки.

- Отсчёт стартует с первого бита. Если бит нет дольше 4 с (пауза/конец
  трека), прогрессия сбрасывается и следующий бит начинает её заново.
- Интенсивность `lvl`: 0.1 → 1.0 линейно за 30 с (`RAMP_SECONDS`).
- Что масштабируется от `lvl`:
  - сфера-звезда бочки: размер/мощь вспышки растёт с уровнем баса
    (`u_kick_energy` / `u_flash_intensity`);
  - снейр/хэт: количество и разлёт искр/лучей;
  - темп спавна osu!-таргетов задаёт метроном (BPM музыки), а не `lvl`.
- Текущий уровень виден в статус-строке (`lvl: 47%`) и в консоли.

Для быстрой проверки на ПК рамп можно ускорить переменной окружения:

```bash
# максимум эффектов уже через 5 секунд
$env:SOUNDGRIP_RAMP = '5'; python main.py --demo
```

| Флаг          | Что делает                                   |
|---------------|----------------------------------------------|
| `--demo`      | демо-паттерн кик+снейр+хэт (120 BPM)         |
| `--loopback`  | только системный звук (soundcard)            |
| `--mic`       | только микрофон (sounddevice)                |
| `--pyaudio`   | только микрофон (pyaudio)                    |

## Как проверить на ПК

1. `python main.py` — в консоли появится строка `Аудио-бекенд: ...`.
2. Включи музыку на ПК: кики дают космические сферы-звёзды и спавнят
   фигуры с approach-кругами, снейр — вспышку с кольцом, хэты — веер
   лучей с искрами (названия полос в логе).
3. Зажми ЛКМ и проведи через фигуру точно в такт бочки — она уничтожена:
   **300** при полностью сжатом кольце, **100/50** если раньше; промах по
   времени (кольцо сжалось без свайпа) — **Miss**.
4. Без музыки спавна нет (тишина = сетка стоит).
5. `python main.py --demo` — синтетический драм-паттерн 120 BPM: видно
   все три типа барабанных эффектов и спавн фигур, без звукового входа.

## Android

- Захват системного звука: `MediaProjection` + `AudioPlaybackCaptureConfiguration`
  (API 29+), поток `USAGE_MEDIA`, формат PCM16 / 48кГц / моно.
- Исправлен краш `autoclass('[]s')` → правильный JVM-дескриптор `autoclass('[S')`.
